# Контекст проекта

Мобильная страница-инструкция по заправкам для водителей (SIA HEAD, HDLG). Один экран: дата действия, баннер про изменения, раскрывающиеся карточки-блоки.

Боевой адрес: https://siahead2017-png.github.io/FuelInstruction/

**Язык общения с пользователем — русский.** Интерфейс тоже только русский. Владелец не программист — объяснять просто, без жаргона.

Родственный проект — [Driver_Instructions](../Driver_Instructions/CLAUDE.md) (тот же владелец, тот же GitHub-аккаунт `siahead2017-png`, но **отдельный репозиторий** и отдельный GitHub Pages сайт). Не путать домены при правках — оба называются похоже по-русски, но это разные `github.io/...` пути.

## Главное правило

**Никакой сборки и никаких зависимостей.** Всё в одном `index.html`: разметка, `<style>`, `<script>` — без React/Vite/бандлеров. GitHub Pages отдаёт файл как есть.

## Данные — не редактируются в коде

Контент (дата, доп. правила, цены на DIESEL, список блоков-инструкций) **не хранится в репозитории**. Он подтягивается на клиенте из Google Таблицы, опубликованной как CSV (`Файл → Опубликовать в интернете`), двумя запросами (см. `index.html`):

- `META_CSV_URL` — лист `Meta` с метаданными: `[0]` метка «Цены обновлены» (реальные дата+время последнего сбора цен — в шапке и в блоках DIESEL/ADBLUE), `[1]` доп. правила, `[2]` цены/станции DIESEL, `[3]` цены/станции ADBLUE (добавлено 05.08.2026, формула `Meta!B4` зеркалит `B3`, источник — вкладка `DIESEL / ADBLUE PRIORITY` строки 23-44 в соседней таблице `Diesel_Price_HEAD_HDLG`, отсортировано по цене формулой `SORT`);
- `BLOCKS_CSV_URL` — лист `Blocks` с блоками инструкций, колонки: заголовок, подзаголовок, основная, резервная, доп. правила, **группа** (колонка F, добавлена 05.08.2026 — см. раздел «Визуальный редизайн» ниже).

**Лист `Blocks` — это НЕ ручной текст, а зеркало вкладки `Рассылка (DAYLI)`.** В той же
Google-таблице есть вкладка `Рассылка (DAYLI)` — исходник ежедневной рассылки водителям.
В ней формулы `VLOOKUP` по вкладке `DIESEL PRICE (DAILY)` каждый день подставляют ту АЗС,
у которой сейчас самая выгодная цена. Колонки **C/D/E листа `Blocks` — формулы**, которые
собирают текст из ячеек `Рассылка (DAYLI)` (например `C2 = 'Рассылка (DAYLI)'!B8`,
`E2 = B15 & " " & B16 & " " & B17`, где `B16` — как раз живой `VLOOKUP`). Вручную в
`Blocks` заполнены только A (заголовок), B (подзаголовок), F (группа) и 4 ячейки
статичных правил: `C13`, `E4`, `E8`, `E14`.

Цепочка целиком: робот `../Diesel_Price_HEAD_HDLG` пишет цены → `Рассылка (DAYLI)`
формулами выбирает станции → `Blocks` их зеркалит → сайт читает `Blocks` как CSV.

⚠️ **Никогда не перезаписывай ячейки `Blocks` значениями.** Если правишь лист через API
(перестановка строк, сортировка), читай диапазон с `value_render_option='FORMULA'` и пиши
обратно с `value_input_option='USER_ENTERED'`. 05.08.2026 при перестановке строк формулы
были прочитаны как значения и записаны обратно текстом — все 32 связи погибли, и до
07.08.2026 сайт показывал водителям устаревшие заправки (VIADA вместо NESTE в Латвии,
Венгрия вместо Чехии по проекту Румыния). Восстановлено из истории версий Google Drive.

Содержимое `[2]`/`[3]` (DIESEL/ADBLUE) — не просто текст, а строки вида `"Страна  /  Станция   -   Карта"` (2+ пробела вокруг `/` и `-` — это разделитель, формула его строит в исходной таблице). Фронтенд разбирает эти строки регуляркой (`parsePriceLine` в `index.html`) и рисует настоящую HTML-таблицу — см. ниже.

Значит: чтобы поменять **текст инструкции**, репозиторий трогать не нужно — правки идут в Google Таблице у владельца. Правки в этом репо нужны только для внешнего вида, иконки, структуры страницы.

`fetch(..., {cache:'no-store'})` — данные не кешируются намеренно, чтобы владелец сразу видел свои правки в таблице.

**Метка «Цены обновлены» (реальное время сбора, июль 2026).** Раньше в шапке была
«Действует с {дата}», где дата = формула `=today()` в `Meta!B1` — она «прыгала» в
полночь сама, не отражая реальный сбор. Теперь `Meta!B1` = `='DIESEL PRICE (DAILY)'!K1`,
а в ячейку `K1` соседнего проекта `../Diesel_Price_HEAD_HDLG` сборщик пишет дату+время
КАЖДОГО успешного сбора (`config.TIMESTAMP_CELL`, см. `utils/sheets.py::write_results`).
Фронт читает эту метку как `metaRows[0][1]` и показывает её в шапке («Цены обновлены: …»)
и дублирует в карточке «Самые Выгодные цены на DIESEL» (плашка `.stamp` «Актуально на: …»).
Формат текстовый «ДД.ММ.ГГГГ ЧЧ:ММ» — не менять на дату-число, иначе локаль переформатирует.

**Идея на будущее: блок «Что изменилось».** Сейчас водитель видит только момент
последнего сбора, но не видит, поменялась ли цена и на сколько. Возможно, добавим
отдельную карточку/строку с историей изменений — «что на что менялось» (было X →
стало Y, по каждой станции/стране), чтобы было видно реальные изменения, а не просто
факт сбора. Для этого `write_results()` в `../Diesel_Price_HEAD_HDLG/utils/sheets.py`
должен будет сравнивать новое значение со старым (`read_results()` там уже есть,
но сейчас нигде не вызывается — пригодится) и копить diff в отдельную ячейку/вкладку,
которую заберёт `Meta`-лист третьей строкой. Не реализовано — только направление.

## Визуальный редизайн (05.08.2026)

Раньше страница была на плоском бежевом фоне с произвольными пастельными цветами карточек — не соответствовала собственному бренду приложения (иконка — тёмная бирюза+медь, `preview.png` — тёмно-синий+янтарь). Владелец также показал референс — Behance-проект Bluedot (тёмная «стеклянная» приборная панель) и попросил гибрид: эффектная тёмная шапка + светлые читаемые карточки (аудитория — дальнобойщики, часто смотрят в телефон на солнце, тёмные карточки читались бы хуже).

**Цветовые токены** (`:root` в `<style>`) — у каждой категории карточек свой цвет, задаётся через CSS-переменную `--glow` (используется и в `border-left`, и в цветной тени-подсветке снизу карточки, «неоновый» эффект по просьбе владельца):
- `--teal` — DIESEL (тот же цвет, что в иконке приложения и `theme_color` манифеста);
- `--blue` — ADBLUE (и карточка цен, и группа блоков ADBLUE ниже);
- `--amber` — «Доп. правила» / баннер;
- `--route` (голубой/циан) — блоки без группы (по умолчанию);
- `--violet` — группа «Работа по БАЛТИИ»; `--green` — группа «Работа в Европе».

**Группы блоков-инструкций.** Колонка `Группа` (F) на листе `Blocks` — если у нескольких подряд идущих строк одинаковое значение, перед первой из них рисуется разделитель (`buildDividerEl` в `index.html`), а сама группа красится своим цветом (`GROUP_CLASS` — словарь «текст группы → CSS-класс», сейчас 3 записи: `Работа по БАЛТИИ`/`Работа в Европе`/`AdBlue`, плюс `ВЫЕЗД / ВОЗВРАТ` без своего цвета). **Порядок карточек на странице = порядок строк в этом листе** — переставить блоки или сменить группу можно, просто переставив строки/поправив колонку F в таблице, код трогать не нужно. Если владелец заведёт новую группу с новым названием — она покажет разделитель автоматически, но цвет будет цвет по умолчанию (`--route`), пока в `GROUP_CLASS` не добавят соответствующую запись.

**Таблица цен (DIESEL/ADBLUE).** `parsePriceLine()` в `index.html` разбирает строку `"Страна  /  Станция   -   Карта"` регуляркой `/^(.*?)\s{2,}\/\s{2,}(.*)\s{2,}-\s{2,}(.*)$/` — рассчитана именно на 2+ пробела вокруг разделителей (так формула строит текст в `Diesel_Price_HEAD_HDLG`), одиночные дефисы внутри названий станций («Vitoria-Gasteiz») не задевает. **Если формулу в исходной таблице когда-нибудь переделают на другие пробелы/разделитель — эта регулярка перестанет находить колонки** и упадёт обратно на «всё одной строкой» (см. `buildPriceTable`, там есть fallback). Ширины колонок в `.price-table` (страна/станция/карта) подобраны руками под самые длинные реальные значения (`AT (INNSBRUCK)`, `CROSSCHEM`, `FR (Lille - Paris)`) — если появится более длинное название страны/карты, может понадобиться снова раздвинуть.

**Остальное:** `body { max-width: 480px; margin: 0 auto; }` — чтобы страница не растягивалась на весь экран при открытии на компьютере (мобильная вёрстка, ширины столбцов в таблице цен считались под узкий экран); `.card` — «стеклянные» карточки (`backdrop-filter: blur()` + мягкий цветной фон страницы из `body`, чтобы блюру было что размывать); намеренно НЕ делали полную тёмную тему и фото-иллюстрации из референса Bluedot — нет фотоассета, и тёмные карточки хуже читаются на солнце.

## Иконка и установка на телефон (июль 2026)

Изначально в проекте не было ни `manifest.webmanifest`, ни `apple-touch-icon` — при установке на главный экран Android/iOS подставляли системную иконку по умолчанию вместо лого. Добавлены оба.

**Кеш: версионные метки `?v=N` — обязательно**, иначе браузер/установленное приложение продолжат показывать старую иконку. При замене любого `icon-*.png` или `favicon.png` поднимай `?v=` сразу в двух местах:

- `index.html` → `<link rel="icon">` и `<link rel="apple-touch-icon">`
- `manifest.webmanifest` → все 4 `src` в `icons`

Сейчас версия `?v=1`.

**Название на главном экране** — два разных поля с разным назначением:
- `name` (манифест) — полное название, показывается в системных диалогах установки/обновления. Сейчас: «DIESEL Инструкция (HEAD, HDLG)».
- `short_name` (манифест) + `apple-mobile-web-app-title` (index.html, для iOS) — короткая подпись **под иконкой** на экране. Длинный текст телефон обрежет (~10-12 символов помещается). Сейчас: «HEAD,HDLG Заправки».

Если владелец меняет название ещё раз — трогать нужно оба поля синхронно (name — для смысла, short_name/apple-mobile-web-app-title — для подписи под иконкой).

При смене имени/иконки уже установленного приложения Chrome/Android покажет диалог-подтверждение «Проверьте новое название» — это штатное поведение (защита от подмены манифеста), нужно нажать «ОК». Сам ярлык на экране не обновляется, пока владелец не подтвердит или не переустановит его.
